## Deepmerge local patch

`backend/patches/deepmerge-4.3.1.json` records exact original/patched SHA-256 hashes and reviewed replacements for `index.js`, `dist/cjs.js` and `dist/umd.js`. The patch rejects `__proto__`, `constructor` and `prototype` keys in both source and target loops, and uses own-property definitions for writes. It protects nested/null-target cases while retaining normal object/array merge behavior, symbol properties, custom merge hooks and `merge.all`.

`backend/scripts/patch-deepmerge.cjs` runs from backend `postinstall`. It validates every file before writing, is idempotent, fails installation on an unknown version/source/result, and skips the absent development dependency for `--omit=dev`. `npm ci` must run lifecycle scripts. If deliberately using `--ignore-scripts`, run `npm run postinstall` before invoking developer tools. No runtime monkey-patch, npm version spoofing or audit suppression is used. Remove/review this patch when upstream publishes a fixed compatible release; an unexpected installed version intentionally fails until reviewed.

Five persistent Node tests reproduce the old defect, validate both published bundle entrypoints, idempotency, unknown source/version rejection, all-file validation before writes, omitted dependencies, normal arrays/objects/symbols and custom array merge behavior. Three controlled before/after payloads changed the returned prototype in the original package; all are rejected by the final patch. The dependency is used by Jest config and fork-ts-checker-webpack-plugin, not by an API input path. A separate production `npm ci --omit=dev` succeeds without installing Deepmerge.
